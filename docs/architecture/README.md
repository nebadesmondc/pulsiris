## Decisions

| Topic | Decision |
|---|---|
| Module communication | Checks publishes `TargetWentDown` / `TargetRecovered` as Spring Modulith events. Events are persisted with the check result and redelivered on failure. |
| Data ownership | One PostgreSQL schema per module. No foreign keys across modules; references are UUIDs. |
| Alerting | Prometheus and Alertmanager evaluate and route alerts. The notifications module receives them by webhook, together with incident events, and delivers to channels. |
| Recovery | A DOWN target recovers after 2 consecutive successful checks. |
| Domain model | Plain Java, no framework annotations. Mapping stays thin, and existing libraries are preferred over custom code. |
| Status columns | Native PostgreSQL `ENUM` types. |
| Identifiers | UUIDv7, generated by the domain when an object is created. |
| Target settings | Defaults and limits come from `pulsiris.targets.*` configuration. Each target can override the defaults within the limits. |
| Validation | Business rules are validated in the domain, and every violation is reported at once. |
| API errors | RFC 9457 Problem Details, with field violations in an `errors` array. |
| Listing | Spring Data `Pageable` for paging and sorting, and JPA Specifications for optional filters bound with `@ModelAttribute`. Page size is capped at 100. |
| API documentation | springdoc OpenAPI. Each module's routes and docs live in an `*Api` interface that its controller implements. |
| Scheduling | ShedLock with the JDBC provider, so checks run on one instance at a time. |
| Duplicate incidents | Prevented by a partial unique index: `UNIQUE (target_id) WHERE status <> 'RESOLVED'`. |
| Retention | Raw check results for 30 days, daily summaries for 13 months, incidents indefinitely. A nightly job aggregates the summaries and deletes expired rows. |
| Target removal | Auto-resolves the open incident with resolution `TARGET_REMOVED`. The target's health state and check history are deleted. |
| Check runs | Every 5 s, due targets are probed in parallel on virtual threads, capped at 50 at a time. Each result is recorded in its own transaction. |
| Probing | JDK `HttpClient`: a timeout per target, redirects followed, TLS certificates verified, response body discarded. Outcomes are `SUCCESS`, `FAILURE`, `TIMEOUT` or `ERROR`. |
